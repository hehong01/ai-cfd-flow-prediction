# 02. SpaceClaim Preprocessing

Convert a watertight head STL into a CFD-ready SpaceClaim model by generating a shrinkwrapped wall, an external-flow enclosure, and the boundary Named Selections required by Fluent.

```text
Watertight STL → Shrinkwrap + CFD enclosure → Named Selections → SCDOC
```

## Input / Output

The default data directories are managed by the repository-level `project_paths.py`.

```text
Input : ai-cfd-data/02_stl/face_XXXX.stl
Output: ai-cfd-data/03_spaceclaim/face_XXXX.scdoc
Log   : ai-cfd-data/03_spaceclaim/logs/face_XXXX.log
```

For the example shown in this folder:

- Input STL: [`../01_image_to_stl/image_to_stl_example_output.stl`](../01_image_to_stl/image_to_stl_example_output.stl)
- Output SCDOC: [`image_to_stl_example_output.scdoc`](./image_to_stl_example_output.scdoc)

### Boundary Named Selections

The preprocessing script automatically creates the four Named Selections used by the downstream Fluent workflow:

- `wall` — shrinkwrapped head surface
- `inlet` — upstream enclosure face
- `outlet` — downstream enclosure face
- `farfield` — the remaining four outer enclosure faces

## Method

### 1. STL Import

`stl_to_scdoc.py` imports the watertight STL generated by `01_image_to_stl` into ANSYS SpaceClaim.

### 2. Temporary Solid Conversion

The imported facial mesh is converted into a temporary solid so that the geometry can be used to generate the shrinkwrapped surface.

### 3. Shrinkwrap Generation

A Shrinkwrap mesh is generated around the head geometry.

The default Shrinkwrap facet size is:

```text
5.0 mm
```

The temporary facial solid is removed after the Shrinkwrap geometry has been created, while the Shrinkwrap body is retained for the CFD model.

### 4. CFD Enclosure Generation

A rectangular enclosure is generated around the head to define the external-flow domain.

The enclosure extensions relative to the head geometry are:

```text
X- / X+ : 500 / 500 mm
Y- / Y+ : 500 / 500 mm
Front   : 500 mm
Back    : 1500 mm
```

The downstream side is intentionally longer to provide additional wake-development space.

### 5. Enclosure Solid Conversion

The generated enclosure mesh is converted into a solid, and planar enclosure faces are merged to obtain the six outer domain faces used for boundary classification.

### 6. Boundary Face Classification

The enclosure faces are classified automatically from their geometric positions rather than from fixed face IDs.

The script identifies:

- the upstream face as `inlet`,
- the downstream face as `outlet`,
- the four lateral/top/bottom faces as `farfield`.

The classification is checked before the Named Selections are created.

### 7. Named Selection Generation

The final SpaceClaim model contains four Named Selections:

```text
wall
inlet
outlet
farfield
```

`wall` is assigned to the shrinkwrapped head surface, while the enclosure faces are assigned to the corresponding flow boundaries.

### 8. SCDOC Export

The completed model is saved as:

```text
face_XXXX.scdoc
```

This file is then used directly by `03_fluent_cfd`.

## Key Implementation Details

### Automated Boundary Classification

The enclosure face IDs can vary between geometries. Instead of hard-coding specific face IDs, `stl_to_scdoc.py` classifies the six outer enclosure faces from their spatial extrema.

This allows the same script to prepare different head geometries without manually redefining `inlet`, `outlet`, and `farfield`.

### Shrinkwrap Resolution and Validated Fallback

The default Shrinkwrap facet size is **5.0 mm**.

During full-pipeline validation, a small number of geometries produced the specific Fluent `Apply Share Topology` self-intersection failure when using the 5 mm SCDOC. Rebuilding those geometries with a **4.0 mm** Shrinkwrap allowed the same CFD workflow to complete successfully.

For this reason, the script exposes the Shrinkwrap size as a command-line option:

```powershell
python .\02_spaceclaim\stl_to_scdoc.py --face face_0001 --shrinkwrap-mm 4.0 --overwrite
```

The repository-level `master_run.py` uses this 4 mm setting only as the validated fallback for that specific Fluent failure.

## Usage

Run from the repository root.

Process all STL files that do not already have an SCDOC:

```powershell
python .\02_spaceclaim\stl_to_scdoc.py
```

Process one face:

```powershell
python .\02_spaceclaim\stl_to_scdoc.py --face face_0001
```

Recreate an existing SCDOC:

```powershell
python .\02_spaceclaim\stl_to_scdoc.py --face face_0001 --overwrite
```

Use a different Shrinkwrap size:

```powershell
python .\02_spaceclaim\stl_to_scdoc.py --face face_0001 --shrinkwrap-mm 4.0 --overwrite
```

Available options:

| Option | Default | Description |
|---|---:|---|
| `--face` | — | Process one face ID or STL filename |
| `--shrinkwrap-mm` | `5.0` | Shrinkwrap facet size in millimeters |
| `--overwrite` | off | Recreate an existing SCDOC |
| `--visible` | off | Run SpaceClaim with the UI visible |
| `--limit` | — | Process only the first N STL files |
| `--spaceclaim` | auto-detect | Explicit path to `SpaceClaim.exe` |

## Output Validation

For each successfully processed STL, the SpaceClaim worker completes the preprocessing sequence and confirms that:

```text
STL imported
Shrinkwrap created
Enclosure created
Boundary faces classified
Named Selections created
SCDOC saved
```

A completed case produces a non-empty `.scdoc` file and its corresponding execution log.
